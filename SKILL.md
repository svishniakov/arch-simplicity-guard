# Architecture Simplicity Guard

Предлагай архитектурно целостные упрощения, включая смену подхода; выбор делает пользователь. Принятое решение остаётся открытым для пересмотра при новых основаниях. Выбор модельных инструкций выполняет код внутри проверяющего агента по его фактической модели.

## Запуск

При автономном вызове создай одного нативного субагента. Предпочитай наследование модели и reasoning/thinking родителя. Если этот способ недоступен, используй штатные настройки субагента той же среды без ручного выбора модели или effort. Передай задачу, материалы или точные пути, ограничения на действия и путь этого скилла, даже если история не наследуется. Субагент выполняет проверку сам и не делегирует её дальше. Если ты уже получил такое поручение как субагент, переходи к получению инструкций в своей сессии.

Читай только инструкцию своей среды:

- [Codex](references/codex.md): нативный fork, при его недоступности обычный spawn.
- [Kimi Code](references/kimi-code.md): один Agent, два последовательных вызова для получения его нативного ID и проверки.
- [Claude Code](references/claude-code.md): нативный fork либо general-purpose, существующий hook; поддержка экспериментальная.

Для Kimi Code нативный загрузчик подставляет session ID здесь: `${KIMI_SESSION_ID}`. Каталог скилла: `${KIMI_SKILL_DIR}`. Передай подставленный session ID субагенту; обычное чтение Markdown не выполняет подстановку. Если остался буквальный placeholder, загрузи скилл через нативный Skill, не угадывай ID по соседним сессиям.

Fallback относится к способу запуска. Он не обходит запрет на субагентов или ограничения разрешений и не запускает перебор моделей при ошибках авторизации, квоты или сети. Не создавай второго проверяющего после успешного запуска первого. Если нативный запуск недоступен, сообщи ограничение; проверка родителем не заменяет независимую проверку.

В Agent Flow применяй скилл внутри уже назначенного архитектора или независимого `reviewer`, без дополнительного субагента. Архитектор использует его при подготовке и пересмотре решения; reviewer — до зависимой реализации и при проверке архитектурных изменений в коде. Применение скилла само по себе не запускает Agent Flow.

## Контракт инструкций

Перед содержательной проверкой получи JSON способом своей среды и прочитай `instructions` целиком. Остальные поля: `model` — фактический ID без подмены alias; `reasoning_effort` — сообщённое средой значение либо `null`; `profile` — путь дополнения относительно скилла либо `null`. Отсутствующий effort не требует перезапуска и не заменяется предположением о его значении.

Код выбирает точное дополнение модели или известного alias, затем дополнение распознанного семейства OpenAI, Claude или Kimi. Неизвестный идентификатор получает только [общие правила](references/core.md) с `profile: null`. Название среды и совместимость API с OpenAI не определяют семейство модели. Таблица находится только в коде; не выбирай дополнение самостоятельно и не передавай модель вручную.

Кратко укажи модель, effort и профиль в обычном отчёте. При запуске со штатными настройками вместо явного наследования отметь способ запуска и причину. Настройки могут отличаться от родительских. При новом review или продолжении в новом turn получай инструкции заново.

При ошибке определения модели или чтения выбранного профиля проверка остаётся невыполненной. Сообщи причину; не подставляй настройки конфигурации вместо фактической модели и не переходи молча к общим правилам. Код гарантирует выбор инструкций; их вызов и содержательное применение остаются обязанностью исполнителя.

## Работа и результат

Область проверки включает процедуры подготовки, изоляции и приёмки, временные скрипты и условия отказа, добавленные при исполнении. Применяй к ним общие критерии; отдельного этапа согласования каждой проверки не требуется.

При подготовке архитектуры используй полученные критерии для выбора решения. При review возвращай конкретные замечания; сам запрос на review не разрешает правки. При поручении пересмотреть решение исправляй его в согласованных границах. Соблюдай условия возврата и завершения из общих правил, включая запрет начинать зависимую реализацию до устранения блокирующих замечаний.

## Сопровождение и новые модели

Codex reader использует SQLite/JSONL, Kimi Code — нативный индекс и JSONL, экспериментальный Claude Code reader — hook и JSONL. Форматы журналов внутренние, а не стабильные публичные API. При их изменении исправляй соответствующий reader и проверяй чтение текущего контекста; не добавляй угадывание модели или сканирование чужих сессий. Python 3.10+ со стандартной библиотекой достаточен.

[Исходная инструкция](references/architecture-simplicity-gate-source.md) — основа для новых модельных адаптаций. Читай её при создании или пересмотре дополнения вместе с официальными рекомендациями разработчика модели; при обычной проверке её повторное чтение не требуется. Не используй адаптацию другой модели вместо исходника и не меняй source ради особенностей модели.

Сохраняй общие предметные требования в `references/core.md`, модельные уточнения — в отдельном файле `references/`. Укажи идентификаторы, источники и отличай рекомендации разработчика от собственных решений. Добавь точное соответствие в `PROFILES` либо подтверждённое правило семейства в `FAMILY_PROFILES` и тест выбора; не дублируй таблицы в инструкциях. При проверке загружай только текст селектора. Семейное дополнение не означает испытание каждой будущей модели или поддержку её агентной среды.
