# Codex

## Автономный вызов

Запусти одного нативного субагента с полным наследованием истории, без `agent_type`, `model` и `reasoning_effort`:

- В collaboration v2: `spawn_agent` с `fork_turns="all"`.
- В CLI v1: `spawn_agent` с `fork_context=true`.

Следуй фактически доступной схеме инструмента. Если полного fork в ней нет, используй обычный spawn без роли, модели и effort: в v2 с `fork_turns="none"`, в v1 без `fork_context`. Это fallback на штатные настройки субагентов, которые могут отличаться от родительских. Не подменяй недоступность всего инструмента, отказ разрешений или сбой сети недоступностью fork.

Передай задачу, материалы, ограничения и абсолютный путь `SKILL.md`. Поручи субагенту выполнить проверку самостоятельно, без дальнейшего делегирования. Получи его результат штатными средствами среды. Новый независимый вызов скилла создаёт нового субагента с актуальными настройками запуска.

## Получение инструкций

Уже выполняющий проверку агент вызывает:

```sh
python3 -B /absolute/path/to/arch-simplicity-guard/scripts/render_instructions.py
```

Разреши путь относительно фактически прочитанного `SKILL.md`. Применяй контракт JSON из него. В интегрированном режиме команда остаётся той же.

Reader использует собственный `CODEX_THREAD_ID`, точную запись `$CODEX_HOME/state_5.sqlite` и текущий `task_started`/`turn_context` собственного журнала. Без `CODEX_HOME` используется `~/.codex`. Родительский `CODEX_SESSION_ID`, конфигурация роли и слова модели не заменяют эти данные. Скопированные при fork `session_meta` родителя не меняют владельца; предыдущий turn не подставляется при отсутствии текущего.

Нативное наследование исследовано в [Codex CLI 0.144.1](https://github.com/openai/codex/blob/db75c19352d29ef29c17dbcf73a7244f1b1a8d10/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs). Обычный spawn учитывает [настройки субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents), поэтому его нельзя описывать как безусловное наследование.
