# Claude Code: экспериментальная интеграция

Подготовлена по документации и проверена на синтетических данных. Работа в настоящем Claude Code и качество review на Claude пока не подтверждены.

## Подключение

Нужен Python 3.10+. Установи скилл в `~/.claude/skills/arch-simplicity-guard` и добавь hook в существующие настройки Claude Code, сохранив остальные записи:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -B \"$HOME/.claude/skills/arch-simplicity-guard/scripts/claude_hook.py\""
          }
        ]
      }
    ]
  }
}
```

При установке в другое место укажи фактический абсолютный путь скрипта. Обычный вызов скилла не разрешает менять настройки среды.

## Использование

- **Автономно:** предпочитай одного нативного fork-субагента с наследованием контекста, модели и effort. Если этот способ недоступен, используй нативного `general-purpose` без переопределений модели и effort: среда применит штатные настройки субагентов. Передай задачу, материалы, ограничения, путь `SKILL.md` и способ запуска; запрети дальнейшее делегирование. Не подменяй недоступность всего `Agent`, отказ разрешений или сетевую ошибку недоступностью fork. Конфигурацию среды не меняй.
- **В Agent Flow:** guard выполняет уже назначенный архитектор или reviewer. Дополнительный агент не нужен. Передай инструкции скилла явно: обычные субагенты не наследуют загруженные skills. Общий `SKILL.md` не должен содержать `context: fork`.

Перед проверкой исполнитель вызывает Bash с точной отдельной командой:

```sh
printf '%s\n' 'arch-simplicity-guard:load'
```

Hook возвращает в `additionalContext` JSON: `model`, `reasoning_effort`, `profile`, `instructions`. Прочитай `instructions` целиком, примени их и укажи модель, effort и профиль в существующем отчёте. При fallback укажи причину использования штатных настроек. Строка от `printf` сама по себе не подтверждает загрузку. Родитель получает результат штатным способом завершения субагента; настройки fork ради синхронного ожидания не меняются.

В новом turn или после смены модели повтори вызов. Модель определяется кодом по точному вызову инструмента в журнале собственного субагента. Настройки модели и effort сохраняются.

## Ограничения

Reader зависит от внутреннего формата JSONL и асинхронной записи журнала. При отсутствии файла или текущей записи hook перечитывает журнал не более двух секунд; остальные ошибки возвращаются сразу. Без доступного hook, текущей записи, модели или необходимого файла инструкций проверка остаётся невыполненной. Отсутствие JSON или `review unperformed` требует сообщить причину; подставлять модель вручную или использовать старый контекст нельзя.

Селектор предпочитает точный профиль, затем дополнение распознанного семейства. Нераспознанный ID получает общие правила. Aliases и provider IDs не угадываются. Неизвестный effort остаётся `null` и не вызывает fallback. Ошибка hook — обратная связь агенту, а не принудительная блокировка его действий.

Экспериментальный статус можно снять после живой проверки наследования, выбора собственной модели, смены модели и доставки инструкций/ошибок в автономном и интегрированном режимах.
