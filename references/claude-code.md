# Claude Code: экспериментальная интеграция

Реализация подготовлена по официальной документации на 2026-10-24 и проверяется синтетическими fixtures. Живой запуск Claude Code, доставка hook-контекста, наследование настроек и эффективность дополнений на Claude не проверены. Не обозначай эту интеграцию как прошедшую эксплуатационную приёмку.

## Установка hook

Помести скилл в `~/.claude/skills/arch-simplicity-guard` либо `.claude/skills/arch-simplicity-guard` проекта. Для селектора нужен Python 3.10+.

Добавь следующий hook в существующие настройки Claude Code, сохранив остальные entries. Пример рассчитан на стандартную пользовательскую установку скилла. При другом расположении замени путь в `command` на фактический абсолютный путь. Сам вызов скилла не разрешает менять настройки среды; подключение выполняется при установке интеграции.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -B \"$HOME/.claude/skills/arch-simplicity-guard/scripts/claude_hook.py\""
          }
        ]
      }
    ]
  }
}
```

Hook обрабатывает только точную команду загрузки ниже. Для остальных Bash-вызовов он заканчивает работу без чтения журналов и без вывода. Новых файлов состояния, credentials и сетевых запросов нет. Ограничения managed settings могут запрещать пользовательские hooks; в таком окружении эта интеграция недоступна.

## Запуск и получение инструкций

В автономном режиме родитель запускает одного нативного fork-субагента с наследованием контекста и модели, без переопределения model/effort. Передай задачу, ограничения, путь `SKILL.md` и указание выполнить проверку самостоятельно без дальнейшего делегирования. Если нативный fork недоступен, обозначь ограничение: обычный агент с иной моделью не заменяет требуемое наследование. Для явного ручного запуска такого fork документация Claude Code описывает `/subtask`.

В интегрированном режиме существующий архитектор или reviewer выполняет guard в своей сессии. Не создавай дополнительного агента. Не добавляй `context: fork` в общий `SKILL.md`: это изменило бы и интегрированный режим. Передавай инструкции скилла явно — обычные субагенты не наследуют загруженные skills автоматически.

Внутри выполняющего проверку субагента перед содержательным review вызови Bash с **точной отдельной командой**, без дополнительных команд и обёрток:

```sh
printf '%s\n' 'arch-simplicity-guard:load'
```

Строка в stdout — только маркер вызова. Нужный результат приходит от `PostToolUse` hook в `additionalContext`: JSON с `model`, `reasoning_effort`, `profile`, `instructions`. Прочитай `instructions` целиком. Укажи модель и профиль в существующем отчёте. Отсутствие этого JSON или сообщение `review unperformed` означает, что зависимая проверка не выполнена; успешный exit самого `printf` ничего не подтверждает. Не выбирай профиль сам и не подставляй идентификатор модели вручную.

В новом turn или после известной смены модели снова выполни команду. Результат характеризует ответ, создавший этот вызов инструмента; он не обещает неизменность модели на следующих API-запросах. Effort берётся из hook, когда поле доступно, иначе возвращается `null`; guard его не меняет.

## Контракт reader и границы достоверности

Нативный hook передаёт `session_id`, `agent_id`, `tool_use_id`, `transcript_path` и необязательный `effort.level`. Reader открывает только журнал указанного субагента: `<каталог-проекта>/<session_id>/subagents/agent-<agent_id>.jsonl`. Поддерживается и прямой путь к этому же журналу в `transcript_path`.

Внутреннее допущение текущего reader: запись имеет `type: assistant`, собственные `sessionId` и `agentId`, объект `message` с `model` и массивом `content`. В нём находится `tool_use` с точным `id`, именем `Bash` и командой-маркером. Остальные аргументы могут быть изменены нативными hooks и не участвуют в сравнении. Только `message.model` этого вызова участвует в выборе. Это форма синтетических fixtures, **не подтверждённая живым журналом Claude Code**. Если реальный формат отличается, reader завершит загрузку ошибкой и потребует уточнения по реальному примеру.

Модель не берётся из родительской истории, имени роли, shell-конфигурации `ANTHROPIC_MODEL` или последней произвольной записи. Короткие aliases и незнакомые provider IDs не преобразуются предположительно: достоверный идентификатор без записи в `PROFILES` получает только core. Отсутствие модели или известного файла дополнения — ошибка.

Transcript записывается асинхронно: текущего вызова может ещё не быть на диске. Загрузка тогда остаётся невыполненной, без подстановки старого контекста. Автоматических повторов и кэша нет. При отключённой записи transcript этот reader работать не может. Hook возвращает ошибку через документированные `decision: block` и `reason` с кодом процесса 0, чтобы Claude получил объяснение; это обратная связь, а не принудительный запрет последующих действий агента.

Перед снятием экспериментального статуса нужна проверка в настоящем Claude Code: standalone fork и существующий reviewer получают собственные модели, повторный turn и смена модели обновляют профиль, параллельные агенты не смешиваются, инструкции и ошибки hook доходят до исполнителя. Необходимость изменения reader определяется результатом этой проверки; установка дополнительных сервисов для неё не нужна.
