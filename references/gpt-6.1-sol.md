# Дополнение для GPT-6.1 Sol

Применяй только для модели `gpt-6.1-sol` вместе с общими правилами [core.md](core.md). Дополнение уточняет способ работы и не заменяет предметные критерии гейта.

- Прежде чем признать механизм лишним, проверь относящихся к нему потребителей и зависимости, включая косвенные: через конфигурацию, обёртки и другие компоненты. Отсутствие прямого вызова не доказывает отсутствие использования. Прослеживай только связи, способные изменить текущий вывод; полный граф проекта не нужен.
- Начни отчёт с вывода: решение принято, требуется пересмотр или конкретную часть нельзя оценить без недостающих данных. Это содержание существующего отчёта, а не новый набор статусов журнала.
- Дай краткое проверяемое обоснование: факты, существенные замечания и ограничения. Не выводи внутренний ход рассуждений и не заполняй отчёт формальными отметками по каждому пункту.

Адаптация подготовлена 2026-10-24 на основе проектной инструкции для Sol. [Карточка модели](https://developers.openai.com/api/docs/models/gpt-6.1-sol) подтверждает её идентификатор. [Руководство GPT-6](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.1-sol#prompting-best-practices) даёт общие рекомендации для семейства, а [Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices#how-to-prompt-reasoning-models-effectively) — рекомендации по ясным критериям и формату результата.

Проверка косвенных связей адаптирует наблюдение из [Maintaining software with the GPT-6 family](https://developers.openai.com/blog/maintaining-software-with-the-gpt-6-family): в описанном сравнении Sol пропускала часть зависимостей feature flags. Это не универсальная характеристика модели. Эффективность дополнения на реальных архитектурных задачах отдельно не измерена.
